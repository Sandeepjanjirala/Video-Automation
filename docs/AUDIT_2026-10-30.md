# Project audit and repairs — 30 October 2026

The current project is a Django/PostgreSQL video creation and export tool. It does
not contain Instagram account connection or publishing code. This repair pass
focuses on the existing script-to-video workflow; it does not add YouTube or plan
the next product phase.

## What was fixed and why

| Area | Verified problem | Change and effect |
|---|---|---|
| Script import | The visible Split into scenes button had no handler. | Implemented local sentence/line splitting with scene limits, preserved script input, and an explicit AI preparation button that submits the user's script. |
| Voice controls | Template IDs differed from JavaScript selectors; the rate slider used multipliers while the backend expects integer percentages; displayed presets were unsupported. | Connected the actual controls, aligned rate units and preset values, and populated voices from provider capabilities. |
| Voice Lab | Preview, normalization, rewrite, history, and candidate containers were disconnected. Scene selection became stale after script splitting. | Reconnected the controls and containers and reset selection when its scene disappears. |
| Editor persistence | Dirty state had two unsynchronized flags. Some voice/library actions replaced unsaved edits with a server snapshot. Recovery, history, and notices targeted missing elements. | Unified dirty reset, saved before server mutations, balanced nested busy state, and repaired notices, recovery, and history. |
| Job display | Existing jobs were not polled on project load; responses could be applied after switching projects. Export cards requested a nonexistent thumbnail and displayed the wrong resolution. | Start polling on project sync, ignore stale project responses, show actual dimensions, and expose prepared voice playback. |
| Draft rendering | Quick draft submitted an ignored `resolution` field, causing a full-quality render. Caption controls were not connected to renderer settings. | Submit `quality=draft`; expose and save actual caption size and bottom margin. |
| Footage search | Frontend expected nonexistent `preview_url`, `download_url`, and `user` fields and called an undefined `Jobs` object. | Match the stock API's `video.url`, `creator`, and numeric video ID contract; use the actual queue module. Global library search supports downloads. |
| Media workflow | Library upload targeted the wrong input ID; offline scene narration upload was absent; footage keywords were hidden. | Connect library upload, add scene recording upload/removal/playback, and expose search keywords. |
| Media location | Upload, playback, and thumbnail endpoints hardcoded the repository's `data/` directory. | Respect `REEL_DATA_DIR` consistently and validate thumbnail paths. Isolated/custom data folders now work. |
| Provider selection | Jobs snapshotted global provider settings instead of project selection. Registry lookup could choose Edge when Azure was requested or silently substitute a default voice. | Snapshot the project provider, resolve voices within that provider, and reject unsupported combinations. |
| Speech consistency | Edited narration could retain old normalized text. Accepting an old take bound old audio to a new script hash. Accepted takes lost their word timings during rendering. | Clear stale derived fields, reject outdated takes transactionally, preserve accepted timing metadata, and honor project delivery presets. |
| Offline controls | Voice Lab bypassed the online-services switch. | Require online permission before uncached synthesis; cached audio remains usable offline. |
| Duplicate delivery | A completed/failed job could acquire a new execution lease and run again. Enqueue checks were vulnerable to concurrent submissions. | Restrict lease acquisition, serialize enqueue decisions with transaction advisory locks compatible with scoped DB roles, and validate operation-key ownership. |
| Cancellation and fencing | A late success/failure update could overwrite cancellation or a newer worker. Local rendering did not use the distributed pipeline's process registration. | Carry execution tokens through job operations, check ownership under the job lock, share the leased pipeline locally and in Celery, and conditionally clear registered process IDs. |
| Process lifecycle | Media timeout cleanup did not reap processes; Linux cancellation could kill the worker's shared process group. | Reap terminated subprocesses, isolate media process sessions on Linux, and only kill a process group when the target is its leader. |
| Recovery and publication | Pre-lease local jobs could remain running after a crash; expired jobs were only recovered at startup locally. Stale attempts could overwrite final artifacts. | Recover legacy interrupted jobs under the local worker lock, check expiries in the local loop, lock publication through completion, and remove failed render working folders. |
| Renderer maintenance | Separate local and Celery render implementations had diverged. | Route local jobs and the compatibility `media.render` entry point through the same pipeline. |
| Speech/render cache | Explicit regeneration still reused old cached audio; scene keys omitted computed cues and audio changes. | Allow explicit cache replacement and include cue data and audio file fingerprint in the new scene-cache version. Existing scene caches are invalidated once. |
| Gemini quota | Daily reservations were not atomic, usage recording counted requests twice, and retry attempts were not individually reserved. Rate-limit results were ignored. | Use an atomic conditional upsert, count each attempt once, reserve retries, honor provider rate limits, and reserve Redis slots atomically. Remove speculative/silent model defaults. |
| Validation | Invalid numeric stock IDs and some Pydantic/settings errors produced server exceptions. Render preflight missed missing assets, stale recordings, invalid trims, and music rights. | Return usable JSON validation errors and reject these render problems before spending time on synthesis/encoding. |
| Stock review | Applying automatically chosen stock clips marked them reviewed without user review. | Require relevance/rights review after applying downloaded footage. |
| Credential handling | Distributed job failures lacked the local worker's secret redaction; migration credentials could replace runtime credentials. | Redact all configured provider secrets from persisted failure messages, separate runtime/migration URL selection, decode URL credentials, and bound DB connection attempts. |
| Fresh installations | Docker omitted templates and fonts, had no migration dependency, and could use credentials inconsistent with the PostgreSQL service. Health/schema checks still required Alembic. | Include templates/fonts, add migration startup ordering, share configured credentials, and use Django schema authority with optional legacy metadata. |
| Migration drift | Fresh databases lacked a default workspace; an asset index in the model was absent from migration state. | Add an idempotent workspace migration and an index migration compatible with databases where the index already exists. Both were applied to the local studio successfully. |
| Setup/documentation | README described removed React/FastAPI/SQLite components and the wrong port. | Replace it with current architecture, setup, recovery, workflow, and isolated test instructions; update the Windows setup message. |

## Limits and remaining product gaps

- Instagram upload/publishing remains unimplemented. The current deliverable is an
  exported video for manual upload. No account was connected and nothing was published.
- No live paid provider calls were made. Provider credentials, current model
  availability, real Telugu pronunciation, and footage relevance need a real-content
  acceptance run. Test narration uses generated tones, not a voice-quality evaluation.
- Celery task functions were exercised directly; this pass did not run a complete
  broker-dispatch-worker deployment or build/redeploy the Docker image.
- DOM interaction tests are not a full visual browser/device test. Long reels,
  sustained load, and production internet hosting are not certified by this audit.
- Historical migration-stage tests remain in the repository. Several use hardcoded
  working databases or obsolete assumptions. They were not run against your saved
  projects and are not included in the 26-test result.
- Rendering still uses simple title cards, stock/uploaded footage, and approximate
  caption alignment. The advanced planning/ranking/renderer prompt documents are
  proposals, not evidence of implemented functionality.
